Root-cause with `getBoundingClientRect()`/`getComputedStyle()`/`elementFromPoint()` via `javascript_tool`, not by guessing from the visual symptom — "element not appearing on screen" has repeatedly turned out to mean "correctly rendered but covered/mispositioned," not "failed to render." Fix via scoped CSS overrides in the react-app's own `index.css` (using the component's `className` prop as the scope hook), never by editing shipped component files.
  - **A component sized/positioned in `em` units relative to its own font-size will silently break once that font-size is overridden smaller** (hit twice: StaggeredMenu's number-badge `right`/`font-size` collapsed its gutter against the label once the item font shrank; ShutterText's `flex-wrap` + fixed-rem font-clamp let a long phrase wrap mid-word). When overriding a shipped/borrowed component's font-size, re-check every other rule that was implicitly sized relative to it (padding, absolute-position offsets, sibling gutters) — don't assume only the text itself changes.
  - **`overflow-x-hidden` + `overflow-y-visible` does NOT give you a genuinely visible y-axis** — per the CSS Overflow spec, pairing `hidden` on one axis with `visible` on the other silently promotes the `visible` value to `auto`, which still passively clips (no scrollbar ever appears to reveal the clipped content). Use `overflow-x-clip` (Tailwind: `overflow-x-clip`) instead of `-hidden` when you need genuinely-visible content on the other axis — `clip` is the one value that doesn't trigger that promotion. Verify with `getComputedStyle(el).overflowY` — if it reads `"auto"` instead of `"visible"`, the promotion happened and you're still clipping. Hit this fixing a descender-clipping bug on ShutterText's per-character wrapper.

- **Claude-in-Chrome automation quirks worth knowing for future frontend verification work:**
  - `requestAnimationFrame`-driven animations (framer-motion, raw rAF loops, etc.) throttle to near-zero when the automated tab is backgrounded/unfocused (`document.hidden === true`), which happens naturally between separate tool calls. A mid-animation screenshot taken this way can look "frozen" even though the code is correct. Workaround: click into the tab (`computer` `left_click`) immediately before checking, ideally in the same batched call.
  - **This got noticeably worse in session 4**: `document.hidden` flapped unpredictably between calls even with a single click-then-check, and having more than one MCP tab open at once made it worse (a second tab silently backgrounds the first — always close tabs you're done with via `tabs_close_mcp` before opening a new one for the same check). Since framer-motion's animation *progress* (not just paint) is rAF-driven, a hidden document doesn't just render a stale frame, it fully pauses the animation's internal clock — even a logically-correct state change (React state flipped, animate target changed) sits inert until the tab is next visible, which can look like a functional bug when it's actually just this. **When verifying animation-timing/gating logic, prefer checks that don't depend on live rAF progress** — event-listener wiring, computed `overflow`/style values, DOM structure/character-position walks via `querySelectorAll` — over trying to catch one specific live mid-animation frame.
  - **Screenshot pixel dimensions do not reliably match `window.innerWidth`/`innerHeight` call-to-call** (observed 1398/1425/1538/1568px-wide screenshots of the same actual browser window across consecutive calls in one session) — manually converting a `getBoundingClientRect()` value into zoom-region pixel coordinates by ratio is unreliable and wastes time. **Prefer `find` (element-reference-based) over manual pixel-coordinate math** when confirming a specific small element is present/clickable; `computer` actions against a `ref_N` are exact regardless of any screenshot/CSS-pixel scale mismatch.
  - Console-log instrumentation + `getComputedStyle`/`getBoundingClientRect` checks are more reliable than screenshot timing for verifying component *logic* (vs. purely visual polish).
