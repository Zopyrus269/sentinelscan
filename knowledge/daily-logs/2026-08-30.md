### Checklist item 4: cross-thread trace propagation, verified live

Two sessions ago this was verified by reading `context.py`'s `snapshot()`/`restore()` in
isolation. This session ran the local dev server on `integration/observability`
(`FIREBASE_SERVICE_ACCOUNT_PATH` pointed at a nonexistent path so nothing wrote to production,

don't correspond to anything real yet. Worth a look if anyone extends the recorder.

### Checklist item 3: demo-data delete-then-reseed, plus a new finding about `uptime/`

While researching this item, found that `scripts/seed_fake_logs.py`'s `_seed_uptime()` writes
`uptime/{date}` documents with a plain `.set()` (no `merge=True`), while the real uptime probe
(`query.py`'s `record_uptime_probe()`, run independently of `SENTINELSCAN_TELEMETRY_ENABLED` by
a separate GitHub Actions workflow) merges into the same date-keyed documents. Session 22's
original seed run therefore likely overwrote whatever real probe history existed for the dates
it touched, with no field in that collection distinguishing real from fake. Flagged to the user
before doing anything; the user's call was to accept the loss and make the uptime history clean
and demo-realistic again rather than attempt any reconstruction. See [[DECISIONS]] for the full
write-up.

Built `scripts/reset_demo_logs.py`: read-only count first (always shown), then, once
`--confirm`ed, a full wipe of `logs`/`presence`/`logs_hourly`/`logs_meta`/`uptime` (all
demo-only while `SENTINELSCAN_TELEMETRY_ENABLED` stays off) plus `stats/{date}` documents scoped
to exactly the date range about to be reseeded (needed because those counters are additive —
`stats` wasn't named in the original handoff note's "safe to blanket-wipe" list, but the same
reasoning applies, and scoping it is required for the reseed's `Increment` counters to come out
correct rather than doubled). Reseeds immediately after by calling `seed_fake_logs.py`'s own
`_seed_day`/`_seed_uptime` helpers directly (no forked copy of that logic). New test file
`tests/test_reset_demo_logs.py` (4 tests: no double-counting on a second run, `stats` deletion
scoped correctly, `uptime` replaced not merged, full-wipe collections end up empty) — needed one
small addition to `tests/_fake_firestore.py`, a `delete()` method on `_FakeDocumentRef` that
didn't exist before.

Dry-run against live production first (read-only, declined the prompt) to show the user exactly
what would be touched, then ran for real with `--confirm` once the user gave the go-ahead:
deleted 126 `logs` + 280 `presence` + 101 `logs_hourly` + 1 `logs_meta` + 15 `uptime` + 7 `stats`
documents, reseeded 280 sessions / 11,927 events / 297 batches / 14 uptime days, rollup processed
141 batches into 88 hourly buckets. Confirmed the reseeded data is actually queryable afterward
via `query.query_events()` and `get_health_snapshot()` against the live project — the property
that mattered, not just "did it write."
