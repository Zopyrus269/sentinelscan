### CI fix: Gitleaks false-positive on graphify's internal cache

PR #4's `Gitleaks Secret Scan` check (this repo's existing `secret-scanning.yml` workflow, added in PR
#1 -- Clyro has no equivalent CI, so this is a divergence from a pure mirror, forced by this repo's own
stricter setup) failed with 4 findings, all `generic-api-key`, all in
`graphify-out/cache/stat-index.json`. Confirmed as a false positive, not a real secret: that file is
graphify's own performance cache, a JSON map of `{file_path: {..., hashes: {file_path: <sha256 of file
contents>}}}` -- the SHA256 hex digests read as high-entropy secret-shaped strings to gitleaks'
entropy-based rule, but they're just content-addressed cache keys, not credentials.

Fixed by `git rm -r --cached graphify-out/cache/` and adding `graphify-out/cache/` to `.gitignore` --
it's a pure local performance cache anyway (rebuilds automatically from file mtimes/hashes on the next
`graphify extract`/`update`), never meaningful to review in a diff, so untracking it is correct
independent of the CI trigger. The rest of `graphify-out/` (`graph.json`, `graph.html`,
`GRAPH_REPORT.md`, `manifest.json`, `.graphify_analysis.json`, `.graphify_labels.json(.sig)`,
`.graphify_root`) stays committed, unaffected.
